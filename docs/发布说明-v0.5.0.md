# mihomo-codex v0.5.0

本版本改进 Windows 的 TUN 权限提示、内核进程回收和系统代理恢复，并将基础连通性与 OpenAI 专项诊断分开判定。

**Windows 10/11 TUN 为实验性功能。** 管理员会话运行方式已经实现，但真实 TUN 路由、DNS 和网络恢复尚未完成整体验收。

## 主要变更

### Windows TUN 管理员会话

- 使用当前应用进程的实际提升令牌判断权限，区分普通会话、管理员会话和检测失败。
- 开启 TUN 前需先从托盘退出应用，再右键选择「以管理员身份运行」。整个应用获得管理员权限，不安装常驻 Windows 服务。
- 设置页显示 Windows 专用权限说明与会话状态，不显示 macOS Helper 的安装、修复、卸载或系统批准入口。
- 关闭主窗口只隐藏到托盘；停止内核或退出应用才结束 TUN 会话。macOS 继续使用原有 Helper 机制。

### Windows 进程生命周期

- 主内核、原生配置校验和版本探测进程在创建时加入私有 Windows Job，避免启动后再绑定产生的未受保护窗口。
- 停止内核、退出应用或应用异常终止时，Job 负责回收受保护的进程树及其子进程。
- 系统代理恢复与进程回收分别处理：正常停止或退出时恢复代理；应用异常终止后，下次启动依据保存的事务快照尝试恢复。

### 系统代理事务与外部接管

- Windows 代理快照记录原始状态 `original`、本次变更前状态 `before`、预期写入状态 `applied` 与提交状态，覆盖接管和恢复被中断的路径。
- 恢复前核对系统当前代理是否仍属于本应用；用户已切到 Clash 等其他客户端时，保留新的代理选择并清理过期快照。
- 临时接管保留代理例外列表，停用原有 PAC；恢复时在仍持有控制权的前提下还原原始 PAC，并保留会话期间用户修改的代理例外。
- 继续读取旧版本 Windows 代理快照，支持升级后的恢复判断。

### 基础连通性与 OpenAI 专项诊断

- Google 和 Cloudflare 是基础目标，至少一个返回预期 HTTP 204 才视为基础连通性通过。
- OpenAI 未认证 Models 接口仍独立检测，以 HTTP 401 为预期状态；失败保留在诊断结果与警告中，不阻止已有基础连通性的代理启动。
- 两个基础目标都失败时仍判定失败；OpenAI 专项成功不能替代基础目标成功。这一判定用于本地代理和 TUN 路由检查。

## 使用与升级

1. 安装对应平台和架构的 v0.5.0 附件，核对 SHA-256 校验值。
2. Windows 普通系统代理可在非管理员会话中使用。切换前关闭其他代理客户端的系统代理或 TUN，避免同时接管。
3. 若要试用 Windows TUN，先从托盘退出应用，再以管理员身份启动；设置页确认「管理员会话已就绪」后开启 TUN。
4. 使用完毕后点击停止或从托盘退出。若应用异常终止，重新打开应用以执行代理快照恢复检查。

应用名称、`com.cmmuu.mihomodesktop` 标识、用户数据目录和 macOS Helper 服务身份继续保留。现有订阅、规则、外观设置和历史版本沿用原有存储，随包 Mihomo 核心仍为 1.19.30。

## 下载

[v0.5.0 GitHub Release](https://github.com/CMMUU/mihomo-codex/releases/tag/v0.5.0) 提供本版本实际构建并上传的附件；仓库和 Release 为私有，需要有仓库访问权限的账号。

- Windows 使用匹配架构的安装包；`.exe` 为 NSIS 安装包，`.msi` 为 MSI 安装包，实际提供格式以附件为准。
- 其他平台仅在对应安装包已上传时提供下载；构建配置或 CI 矩阵不代表已完成该平台安装与网络接管验收。
- `SHA256SUMS.txt` 记录发布附件的 SHA-256 校验值。
- `mihomo-v1.19.30-source.tar.gz` 与 `Mihomo-LICENSE-v1.19.30.txt` 对应随包核心的上游源码和 GPL v3 许可证。
- GitHub Source code 压缩包对应 `v0.5.0` 标签的应用源码。

Windows 可用 PowerShell 计算所下载文件的校验值，再与 `SHA256SUMS.txt` 中同名文件一行比较：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\下载的安装包文件名.exe'
```
