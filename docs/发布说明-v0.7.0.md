# RouteDeck v0.7.0

## 内置双渠道更新

- 设置中可选择自动、GitHub 或 Gitee。自动模式比较可用渠道的稳定版本；某个渠道不可用或镜像落后时会明确提示，不会降级本地应用。
- 支持软件内下载、进度显示、取消和重试。下载包必须通过官方 Minisign 签名、SHA-256 摘要及大小校验。自动下载默认关闭，可在设置中开启。
- 自动检查在启动后延迟执行，随后每 6 小时检查一次。安装始终需要再次确认；确认前不会停止代理、关闭程序或重启电脑。
- 安装前安全恢复系统代理并停止本应用的内核。安装会短暂中断连接，RouteDeck 重新打开后需按需要启动代理。Windows 系统可能显示安装进度或权限提示。
- 两个渠道使用相同安装包和签名，下载地址各自独立。只有版本、摘要、大小和签名全部相同，才允许下载时跨渠道回退。

## 稳定性与程序管理

本版包含此前本地 0.6.0 / 0.6.1 中的改动：订阅 403 的有界请求头兼容重试、Windows 系统代理地址格式兼容、避免未变化订阅触发重新加载、隐藏 OpenAI 容灾测速子进程控制台、程序代理新增/编辑/删除和显式启动，以及统一导航和滚动条圆角。

程序代理只影响由 RouteDeck 新启动且支持相应代理参数/环境变量的程序，不会强制拦截任意进程，也不会结束已运行的应用。Codex 的实际长会话稳定性仍需在用户方便时验收。

## 升级与版本一致性

旧版 0.6.x 只有发布页面入口或不具备此更新机制，需要一次性手动安装 **正式发布渠道中的 0.7.0 包**。不要将同版本的本地候选构建当作正式发布包；CI 重建的摘要可能不同。

安装前结束重要会话、从托盘退出 RouteDeck，并备份数据目录。应用身份及原数据目录保持不变。Windows NSIS/MSI 使用对应的更新格式；macOS 使用签名更新归档；Linux 内置更新仅适用于 AppImage，deb/rpm 使用原包管理方式更新。

安装完成后核对软件“设置”中的版本和系统文件版本。发布清单、安装包名称、源码版本和发布标签在 CI 中进行一致性检查，发布附件还需验证摘要和签名。

## 发布状态说明

此文件是用于 v0.7.0 发版的说明，不证明该版本已经公开发布。GitHub/Gitee 发版成功及各渠道附件验证通过后，才可宣称本地安装与正式发布同步。生成更新签名不等于 Windows Authenticode 代码签名或 Apple 公证。
